## Design

### BLD-10 — "Grow my company" reaches kickoff, not a dead-end login wall (5 pts)

`Start.tsx`'s `goBuild()` currently branches on `path` (local component state, `'new' | 'grow'`) and only the `'new'` branch does anything useful (`dispatch({type:'GOTO_SCREEN', screen:'build'})` → eventually `Intake`). Fix: the `'grow'` branch gets the same dispatch, plus a new `dispatch({type:'SET_GROWTH_INTENT', value:true})` (a new, minimal `BuildAction` added to `lib/build/state.ts`'s union, mirroring `SET_BRAND_DRAFT`'s "pure data, no side effect" shape: `{type:'SET_GROWTH_INTENT', value:boolean}`, reducer case `return {...state, growthIntent: action.value}`). `KickoffQuestions.tsx`'s existing `getKickoffQuestions(state.track, false)` call (the literal `false` is a hard-coded placeholder from Epic 3 — confirmed by direct read of `KickoffQuestions.tsx:28`) becomes `getKickoffQuestions(state.track, state.growthIntent ?? false)`, which activates the already-written, already-tested `COMPANY_GROW_BUSINESS_QUESTIONS` set with zero changes to `kickoff-questions.ts` itself. `Intake.tsx` is reached identically from both paths — no duplication of the brand-naming/idea-entry step.

### BLD-08 — remove internal jargon from user-facing copy (5 pts)

Two real defects, one real fix pattern:
1. **`ARTIFACT_TITLES` itself needs plain-language entries.** Change `dataModel` → `'Your data model'`, `memoryPolicy` → `'What Cody remembers'`, `thesis` → `'Your business thesis'`, `wedge` → `'Your first customers'` (keep the rest — `'Product Brief'`, `'Business Model'`, etc. — already plain). This is a content-only change to the existing map in `lib/build/titles.ts`, no structural change.
2. **`JourneyBar.tsx:77` must look up `ARTIFACT_TITLES[v] ?? v` instead of rendering `v` raw** — one-line fix, same import pattern `BuildOverlays.tsx` already uses.
3. **Literal "swarm"/"autonomous loop" strings** in `Pricing.tsx`, `Account.tsx`, `BuildOverlays.tsx`, `AutoModePanel.tsx`, `DocumentsPanel.tsx`, `OnboardingVideo.tsx`, `LiveTicker.tsx` are replaced with plain equivalents on a per-string basis (e.g. "agent swarm" → "Cody's team of AI workers"; "nightly autonomous loop" → "Cody keeps working overnight"), each a direct content substitution with no new mechanism — this is copy editing across 7 files, not a redesign. `ArtifactFrame.tsx`'s `ARTIFACT_ID` chips (`PRD-01` etc.) are explicitly OUT of scope per the backlog doc's own allowance for secondary technical labels alongside a plain title.

### BLD-11 — landing page explains what you get, handles physical businesses (8 pts)

New section inserted between the existing beat 1 ("You Are Not Alone") and beat 2 ("A cofounder from another world") in `Landing.tsx`: a real "What you get" explainer — plain-language enumeration of concrete deliverables (a working app or a real business plan + website + initial customers, depending on track) rather than process language ("ship", "pipeline", "deploy"). A new sentence addressing physical/local businesses explicitly (e.g., "Running a bakery, a gym, a landscaping company? Cody builds the website, intake forms, and customer pipeline — no code, no software background needed") is added to this new section, since today's copy has zero acknowledgment that `track === 'company'` covers non-software businesses at all (confirmed: `Fork.tsx`'s real "Grow my company"/"Create a new company" split already implies this breadth, but `Landing.tsx`'s hero copy never says so). `Auth.tsx:28-29`'s subtitle strings get the same plain-language pass: `"Compose intelligent products and AI-native companies."` → something naming concrete outcomes instead of "primitives"/"building blocks" (e.g. "Describe your idea. Cody builds the website, the plan, and the first customers.").

### BLD-09 — positioning prompt softened + minimal eval harness (5 pts)

`lib/build/artifact-prompts.ts:95-101`'s hard-coded `'unlike (array of 3 "unlike the alternatives" contrasts)'` instruction is replaced with softer guidance that does not force a combative "unlike X" framing on every generated positioning artifact — e.g. "differentiators (array of up to 3 things that make this company distinct, phrased positively rather than as contrasts against named competitors)". Since no prompt-eval infrastructure exists anywhere in this repo, this story adds the FIRST one, minimally: a new `__tests__/lib/build/artifact-prompts-positioning.test.ts` that calls the real prompt-building function (not the LLM — the prompt template itself) and asserts the output prompt string does NOT contain the literal word "unlike", pinning the fix so a future edit can't silently reintroduce the pattern. This is a deliberately narrow eval (string-content assertion on the prompt template), not a new LLM-output-quality grading system — building a real output-quality eval harness is a separate, larger initiative out of scope for this story's point count.

### SEP-06 — usage-based pricing message during generation (3 pts)

New, small addition to `BuildOverlays.tsx`: a fourth, optional sub-copy line shown only on the `swarm` and `infra` overlay kinds (the longest-running, most resource-intensive generation stages — confirmed via `BuildOverlays.tsx`'s own three overlay kinds), reading a short usage-aware message (e.g., "This build uses your plan's included generation credits — no surprise charges"). The message is static per-overlay-kind copy (not a live cost calculation — no real-time cost-metering mechanism exists anywhere in this codebase to compute an actual dollar figure, confirmed via the same grep that found no usage-messaging slot at all), stored as a plain string constant alongside the existing fixed headline/sub-copy for each overlay kind, following the exact same "fixed copy per overlay kind" pattern `BuildOverlays.tsx` already uses for its headline and sub-copy — genuinely new content slot, zero new mechanism.

## Review Focus

- **Stale `growthIntent` across a repeat visit**: a user who completes a "new business" kickoff, then later returns and picks "Grow my company" without the app state resetting, could see `growthIntent` still `false` from a prior session if `BuildState` isn't properly reset between distinct `GOTO_SCREEN` entries to `'build'`. Test: dispatching `SET_GROWTH_INTENT` with `true` then re-entering via the "new business" path explicitly dispatches `SET_GROWTH_INTENT` with `false` (both `Start.tsx` branches always set the flag, never leave it unset from a prior value).
- **`ARTIFACT_TITLES` fallback for an unmapped view id**: `JourneyBar.tsx`'s fix (`ARTIFACT_TITLES[v] ?? v`) must not silently show `undefined` if a future view id is added without a title — the `?? v` fallback (same pattern `BuildOverlays.tsx:41` already uses) is required, not optional, and gets its own test.
- **BLD-11's physical-business sentence must not break the App track's copy** — `Landing.tsx`'s new section is shown identically regardless of which track (`app`/`company`) the visitor eventually picks (the landing page is pre-track-selection), so the new copy must read sensibly for a software-app visitor too, not only a physical-business one. Test/review check: the new sentence names BOTH example classes ("a working app" and "a bakery, a gym...") rather than assuming company-track only.
- **BLD-09's eval test must assert on the real exported prompt-building function**, not a hand-copied string duplicate of the prompt — a test that re-implements its own expected prompt text would pass even if `artifact-prompts.ts` regressed back to "unlike" wording, defeating the pinning purpose.
- **SEP-06's static usage message must not claim a real dollar amount or specific credit count** that isn't backed by a real metering call — since no metering mechanism is being added in this story, the copy must stay genuinely generic ("included in your plan") rather than imply a precision the system can't deliver, to avoid a support/trust issue if the message is ever wrong for a given plan tier.
