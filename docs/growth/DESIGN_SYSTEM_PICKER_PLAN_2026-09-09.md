# Design System Picker — Implementation Plan

**Date:** 2026-09-09 · **Owner:** eng · **Status:** MVP scoping complete, implementation starting

## What this is

Two asset drops were provided:
- `~/Downloads/Design systems for builder product/` — **40 complete design systems** (`systems/<name>/theme.json` + compiled `styles.css` with OKLCH tonal ramps + AIKit `--a2ui-*` variable aliases + 8 live component-demo HTML files each), plus a deterministic theme→CSS compiler (`_gen/generate.js`), plus confirmation that **Modernist — Builder's own current chrome — is itself one of these 40 systems**, exported in the identical format.
- `~/Downloads/design_system-V1/` — a lighter, ~19-system companion set using the W3C Design Tokens format (`$type`/`$value`), with generic spec-sheet docs (not Builder integration code).

**Decision (confirmed with Toby, 2026-09-09):** folder 1 is the source of truth — it's the complete, production-ready asset, and it already includes Modernist, confirming this export format is the intended integration path. Folder 2 is not used for the MVP.

**Scope decision:** ship the real end-to-end mechanism with a curated 6-system MVP first, then backlog the remaining ~34 systems as a batch-import follow-up. Building all 40 blind before the picker/apply mechanism exists would be wasted effort if the mechanism needs to change shape.

## Real, existing integration point (confirmed in code, not assumed)

Builder **already has** a working theme-injection mechanism for generated-app codegen — this is not a new pipeline, it's an existing one to extend:

- `lib/theme-system.ts` — `ThemePalette` (primary/primaryHover/dark/secondary/light/accent/neutral colors), `THEMES` (20 hardcoded palettes), `selectTheme(prompt)` (keyword-matches or hashes the idea text to auto-pick one — **no user choice exists today**), `formatThemeForPrompt(theme)` (renders a "COLOR THEME" prompt section), `applyThemeToPrompt(prompt, theme)` (replaces `THEME_PRIMARY`/`SECONDARY`/`ACCENT`/`DARK` placeholders in `PROFESSIONAL_SYSTEM_PROMPT`).
- **Single call site:** `app/api/chat-ws/route.ts:360-368` — `selectTheme(message)` → `formatThemeForPrompt` → `applyThemeToPrompt(PROFESSIONAL_SYSTEM_PROMPT, ...)`.
- Separately, `state.brandColor` (`lib/build/state.ts`) is a single cosmetic hex string, auto-generated by Cody in `Intake.tsx`, used only in preview/media UI (`MediaPanel`, `DocumentsPanel`, `Preview.tsx`) — **it never reaches codegen at all today**. Not the right field to extend; `theme-system.ts` is.

**The MVP mechanism:** let the founder explicitly pick one of the 6 imported systems in a new build-flow step; store the choice; have `chat-ws` use the chosen system's real palette + fonts instead of `selectTheme`'s auto-pick, via the same `formatThemeForPrompt`/`applyThemeToPrompt` shape (extended to carry font family + a few more real tokens the source systems have that `ThemePalette` doesn't yet: `radius`, `shadows`, `density`, `imageTreatment`).

## Real source data shape (confirmed by reading actual files)

`systems/<name>/theme.json` (flat, e.g. Noir):
```json
{
  "name": "Noir", "series": "foundation", "primitive": null,
  "palette": { "band": "dark", "bg": "#101010", "surface": "#181818", "text": "#f2efe9",
    "accent": "#c9b27c", "accent2": "#f2efe9",
    "status": { "running": "#c9b27c", "success": "#81bb8d", "warning": "#dbb879", "error": "#de958e", "info": "#7fafe2" } },
  "fonts": { "heading": { "family": "Cormorant", "weights": [300,400,500] },
             "body": { "family": "Jost", "weights": [300,400,500] } },
  "density": 1.2, "radius": 0, "layoutStyle": "flow", "shadows": "none",
  "imageTreatment": "grayscale", "brandBound": false,
  "effects": { "glass": false, "metallic": false, "wobble": false, "backgroundGrid": false }
}
```
`components/*.html` (8 files per system: agents/buttons/cards/data/dialog/forms/navigation/table) are live, styled HTML demos of both standard UI and an AI-native component layer (`.agent`, `.status-dot`, `.run-step`, `.stream-chunk`, `.tool[data-state]`, `.composer`, `.meter`, `.log-row`) — real reference markup, useful for the picker's live preview.

**No embedded fonts in either folder** (confirmed via exhaustive find) — every font is a bare family name intended to load from Google Fonts. The MVP must load fonts via `next/font/google` or a `<link>` tag per selected system, not assume files exist.

## MVP system selection (6, deliberately diverse)

| System | Series | Ground | Heading font | Why picked |
|---|---|---|---|---|
| **Modernist** | (Builder's own) | light | Archivo | Already live — the default/baseline; proves the picker includes "keep what you have" |
| **Noir** | foundation | dark | Cormorant | Luxury/editorial — strong dark-mode, serif-adjacent contrast to Modernist |
| **Crayon** | foundation | light | Fredoka | Playful/toy — light, rounded, maximally different feel |
| **Cody** | ainative (`brandBound: true`) | dark | Geist Mono | AINative-primitive-bound (embodies Cody the CTO agent) — proves the `primitive`/`brandBound` field matters |
| **Outrun** | foundation | dark | Orbitron | Neo-retro 80s — bold, distinct visual identity, stress-tests very different aesthetics |
| **Ledger** | ainative (`brandBound: true`) | light | Libre Franklin | Data/cost-accounting direction — a second AINative-bound system, light-mode counterpart to Cody |

## Implementation slices (see backlog issues for exact scope/tests per slice)

1. **Data import** — copy the 6 systems' `theme.json` + `styles.css` + `components/*.html` into the real codebase (`lib/design-systems/`), write a typed `DesignSystem` schema + a `DESIGN_SYSTEMS` catalog array, unit-tested.
2. **Picker screen** — a new `design` screen in the build flow (`fork → intake → design → ws`), showing the 6 systems as selectable cards (name, direction, a live color/font preview), persisting the choice into `BuildState`.
3. **Codegen wiring** — extend `lib/theme-system.ts` (or a new sibling module) so a chosen `DesignSystem` can produce the same `formatThemeForPrompt`/`applyThemeToPrompt` shape `chat-ws` already consumes, richer where the source data allows (fonts, radius, shadows). Falls back to today's `selectTheme` auto-pick when no system was chosen (never a breaking change for existing flows).
4. **Font loading** — load the chosen system's Google Fonts (heading + body family) into the generated app's real output, not just the picker UI.
5. **Persistence** — store the chosen system id on the company record (same place `appSub`/`brandColor` persist today) so it survives reload and is available to a later "edit" pass.
6. **Follow-up (separate epic, not in this pass):** batch-import the remaining ~34 folder-1 systems using the same schema/pipeline slice 1 establishes.

## What's explicitly NOT in this pass

- Folder 2's W3C-token systems (not adopted per the sourcing decision above).
- The remaining ~34 folder-1 systems beyond the 6 MVP picks (tracked as a separate follow-up issue).
- Any UI/behavior change to Builder's OWN chrome (`app/modernist.css`) — this feature is about the *generated app's* look, not Builder's own.
- Post-deployment re-theming of an already-built app (out of scope — same "chat can't edit existing app" gap as issue #582; a design-system change today only applies to a fresh generation).
